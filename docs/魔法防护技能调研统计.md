# 魔法防护技能调研统计（2026-09-14）

> 目的：技能树缺少**魔法相关防护**，调研 Enigmatic Legacy / Champions / Champions Unofficial / L2Hostility / Confluence 后，统计可借鉴的机制与新增技能候选。

| 分组 | 数量 | 防护相关技能 |

| MAGIC 魔法增幅 | 15 | ⚠️ **全是"输出/资源"类**（魔力增幅、恢复、吟唱缩减、各系法术强化）——**零防护** |

| GIFT 馈赠 | 11 | — |

### 🔴 缺口（逐项对照后确认）

1. **没有任何"魔法伤害减免"** —— 现有护甲只减物理；原版魔法伤害（药水/龙息/凋零/法术）穿甲，玩家点满 BODY/TOUGH 也照样挨满
2. **没有"魔法抗性"这一维度** —— 原版 `Attributes` 无此属性，需自建（我们已有 3 个自建属性先例）
3. **没有"按伤害类型"分级防护** —— 没有"免疫 X / 抗 Y / 易伤 Z"的结构
4. **没有"减伤上限"约束** —— ULT_VOID_BODY 已是三层无敌，再叠很容易做成真无敌
5. **没有"抗性↔易伤"平衡** —— 只加抗性不加代价，会破坏平衡
6. **没有"反制施法者"的机制** —— 如驱散敌人增益、反射法术、法术吸收

## 二、参考模组的防护机制（源码级）

### A. L2Hostility（莱特兰-恶意）★ 最完整的"魔法/物理"伤害分类

**核心：它把伤害分成 MAGIC / DIRECT 两大类，并定义两种"穿透"状态**

```java
// init/data/LHDamageTypes.java —— 伤害类型带标签
new DamageTypeHolder(KILLER_AURA, ...).add(DamageTypeTags.BYPASSES_ARMOR, L2DamageTypes.MAGIC);
// content/traits/legendary/DementorTrait.java —— 伤害无视护甲
event.enable(DefaultDamageState.BYPASS_ARMOR);
// content/traits/legendary/DispellTrait.java —— 伤害无视魔法保护
event.enable(DefaultDamageState.BYPASS_MAGIC);
```

**词条（防护侧）**

| 词条 | 效果 | 关键实现 |
|---|---|---|
| **Dementor 摄魂怪** | 抗**物理**伤害；自身伤害无视护甲 | `nonlinearPre` 非线性减伤 |
| **Dispell 驱散** | 抗**魔法**伤害；伤害无视魔抗；随机封印敌人附魔 | 同上 + 附魔禁用 |
| **Adaptive 适应** | 记忆受过的伤害类型，同类型每次叠加减伤 | `DamageData`（name + count） |
| **Reflect 反射** | 把物理伤害**反射为魔法伤害** | 新建 `REFLECT` 伤害类型，防递归 |
| **Protection 保护** | 自身获得抗性提升（`DAMAGE_RESISTANCE`） | `SelfEffectTrait` |
| **Arena 竞技场** | 免疫"不受此效果影响实体"的伤害 | `nonlinearFinal(12345, e -> 0)` |
| **Undying 不死** | 死亡即回满血 | `onDeath` |

**★★ 最值得学：非线性减伤公式（避免无敌）**
```java
// 低伤害 → 线性削减（val/def）；高伤害 → 对数削减（log(val)/log(def)）
// 即：小刀砍不动，大剑仍能造成可观伤害 —— 天然防无敌
cache.addDealtModifier(DamageModifier.nonlinearPre(7435, 
    val -> (float)(val < def ? val / def : Math.log(val) / Math.log(def))));
```

**玩家侧防护装备（LangData）**
| 装备 | 效果 |
|---|---|
| **神圣之戒 Ring of Divinity** | **完全免疫魔法伤害** + 永久净化效果 |
| 反射之戒 Ring of Reflection | 负面效果**反弹给周围敌人** |
| 想象破坏者 Imagine Breaker | 近战**无视魔法保护**（反制手段） |
| 白金之星 Platinum Star | 近战无视**伤害冷却** |
| 绝缘体附魔 INSULATOR | 减少"推/拉"类词条影响 |

### B. Champions / Champions Unofficial（冠军·强敌）★ 防护词缀的完整实现

**词缀分三类**：`AffixCategory.CC / OFFENSE / DEFENSE`

| 词缀 | 分类 | 效果 | 关键实现 |
|---|---|---|---|
| **Shielding 防护** | DEFENSE | 每 40 tick 概率切换"免伤态" | `onAttacked` 返回 **false** = 完全免伤 |
| **Adaptable 适应** | DEFENSE | 同伤害类型连续攻击递减，**且有硬上限** | 见下 |
| **Dampening 抑制** | DEFENSE | **只减"间接伤害"**（箭矢/弹射物） | `source.isIndirect()` |
| **Reflective 反射** | OFFENSE | 反射伤害，有**上限**且**可选不致死** | 新建 `REFLECTION_DAMAGE` + 防递归 |
| **Lively 活力** | — | 受击记录时间；无攻击时每秒回血 | `AffixData.IntegerData` |
| **Wounding 创伤** | OFFENSE | 目标获"创伤"：**治疗 ×0.5、受伤 ×1.5** | `LivingHealEvent` + `LivingDamageEvent` |
| Molten 熔融 | OFFENSE | 攻击力 + 护甲穿透 | 属性修饰符 |
| Plagued 瘟疫 | OFFENSE | 给附近生物凋零 | — |

**★★ 精髓三则**

1. **减伤必须设上限 + 下限地板**
```java
// AdaptableAffix：递减但有最大减伤率，且不会低于 amount*(1-max)
newAmount -= amount * increment * count;
return Math.max(amount * (1.0f - maxReduction), newAmount);
```

2. **反射/免伤必须防递归**
```java
// ReflectiveAffix：来源已是反射伤害或荆棘 → 直接返回，不再反射
if (source.is(REFLECTION_DAMAGE) || source.is(DamageTypes.THORNS)) return newAmount;
// 另有"反射不致死"选项（防止被反弹秒杀）
if (!reflectiveLethal && currentDamage >= living.getHealth()) evt.setAmount(living.getHealth() - 1);
```

3. **"抑制"只针对间接伤害** —— 这是"物理 vs 魔法"的另一种切法：近战全额、远程/法术减免

## 三·补、🔴 现有「终极防护链」现状核查（2026-09-14 补充，重要）

新增技能前必须搞清现状，否则会做出"被终极完全覆盖"的废技能。核查结果如下。

### 现有终极防御链结构

```
终极层（4 个并列）
  浴血奋战 ULT_BLOOD ─┐
  不坏金身 ULT_GOLDEN ├─→ 全能精通 ULT_MASTER ─→ 虚空神体 ULT_VOID_BODY
  凤凰涅槃 ULT_REVIVE │      (毕业节点)              (终极毕业)
  死神凝视 ULT_REAPER ─┘
```

**前置关系（`Skills.getPrerequisites`）**
```java
case ULT_MASTER    -> List.of(ULT_BLOOD 1, ULT_GOLDEN 1, ULT_REVIVE 1, ULT_REAPER 1);
case ULT_VOID_BODY -> List.of(ULT_MASTER 1);   // 唯一前置
```

### 全能精通 ULT_MASTER（下界之星图标）
| 效果 | 实现 | 关键配置默认值 |
|---|---|---|
| **全伤害减免** | `onLivingIncomingDamage` 百分比削减 | ★ `masterDamageReduction = 1.0` = **100% 免疫**（含真伤/混沌/指令） |
| 免死保底 | `onLivingDeath` 回血 50% + 清负面 + 3 秒无敌，进冷却 | `undyingCooldown = 1200`(1分) / `undyingInvuln` |
| 冷却中保 1 血 | 同上 else 分支 | — |
| 负面效果免疫 | 每 10 tick 清除所有非有益效果 | — |
| 火焰免疫 / 溺水免疫 | 持续灭火 + 空气恒满 | — |
| 摔落免疫 / 击退免疫 | `LivingFallEvent` / `LivingKnockBackEvent` cancel | — |
| 属性增幅 | 全基础属性 ×(1+0.25) | `masterBonus = 0.25` |
| **代价** | 技能点获取 −20% | `masterSkillPointRate = 0.8` |
| 消耗 | `ULT_MASTER_COST`（一次性） | — |

### 虚空神体 ULT_VOID_BODY（钻石甲图标）
| 效果 | 实现 |
|---|---|
| **全伤害完全免疫** | `event.setAmount(0)` —— 所有类型，**优先于全能精通** |
| **绝对不死** | `onLivingDeath` 直接 cancel + 回满血，**无冷却** |
| 血量只增不减 | 每 5 tick 回满 |
| 常驻吸收 20（10 黄心） | 无限时长 ABSORPTION amp=4 |
| 氧气无限 / 灭火 / 清负面 / 虚空救援 | 同全能精通并加强 |
| 摔落免疫 / 击退免疫 | 同 |
| 消耗 | `voidBodyCost = 5000`（一次性） |

### 🔴🔴 由此暴露的三个结构问题

1. **全能精通默认就是 100% 全伤害免疫** → 它已经"无敌"了。
   那么"缺少魔法防护"这个诉求，**只对"未毕业玩家"成立**；一旦点出全能精通，任何新增的低阶防护技能都**毫无边际价值**。

2. **虚空神体相对全能精通的增量很小** —— 两者都是全免疫，虚空只多了"血量恒满 + 无冷却免死"。
   两个无敌节点串联，层级感弱。

3. **"全能"名不副实** —— 它的 4 个前置（浴血/不坏/涅槃/死神）全是**进攻与生存**类，
   **不含任何"元素/魔法防护"维度**。叫"全能"却没有"魔防"这一支，正是用户感觉"缺魔法防护"的根源。

### ✅ 结论：新增技能必须同时做"链路改造"，否则无效

即用户所指的「**新增的话对应的也要增加前置和增强**」。三种可选改造方案（待用户选）：

| 方案 | 做法 | 效果 | 风险 |
|---|---|---|---|
| **A. 并入前置链** | 新增 3~4 个魔法防护终极技，**加进 ULT_MASTER 的前置列表** | "全能"名副其实；必须掌握魔防才能毕业 | 毕业成本大幅上升（前置从 4 个变 7~8 个） |
| **B. 降级终极免疫** | 把 `masterDamageReduction` 默认从 `1.0` 降到如 `0.6`，**剩余部分靠新增的魔防技能补足** | 形成"渐进防护"层次；魔防技能有真实价值 | 改动现有平衡，老玩家体感变化 |
| **C. 中间层独立** | 新增技能做成 MAGIC 列的"过渡防护"，终极保持无敌 | 改动最小 | 边际价值低（毕业后无用），问题 1 未解决 |

> 推荐：**A + B 组合** —— 新增魔防终极作为前置（A）；
> 同时把全能精通的"全伤害 100% 免疫"调整为"物理/魔法分维度、需前置补全"（B），
> 让"毕业 = 真无敌"仍然成立，但**路径上体现了魔防的价值**。

## 四、设计铁律（从参考模组提炼，实施时必须遵守）

1. **减伤必须有上限**，绝不做成"100% 免疫"（L2H 用非线性公式，Champions 用 `maxReduction` 地板）
2. **反射/免伤必须防递归**（判定来源伤害类型，`THORNS` 与自定义反射类型直接放行）
3. **反射可选"不致死"**（避免玩家被自己的反射害死）
4. **有抗性就要有代价/易伤**（Enigmatic：烈焰之心抗火但近战易伤；傀儡之心抗近战但魔法易伤）
5. **免疫用白名单，抗性用带符号倍率**（`>1` 表示易伤），不要混成一个字段
6. **按 `DamageType` 标签判定**，不要按字符串比对（Enigmatic/L2H 都用 `ResourceKey<DamageType>`）
7. **魔法抗性走自建属性**（原版没有），与现有 3 个自建属性同一套注册/上限/持久化流程
8. 所有文本走语言文件（4 文件双语），图标选贴切原版物品

### 关键设计决策

1. **魔法伤害用「标签推导」而非自建伤害类型**：`BYPASSES_ARMOR && !BYPASSES_INVULNERABILITY`
   —— 零成本覆盖所有模组的魔法伤害，且自动排除 `/kill`、虚空这类不该减免的伤害
2. **减伤用 MOBA 公式 `D/(D+K)`**：减伤率永不到 100%，但 EHP 线性增长 → 每级等值、天然不无敌、可无限扩级
3. **多层减伤用 `1-(1-a)(1-b)`**：直接相加会在高等级溢出成 100%（= 变相无敌）
4. **反射不致死 + 防递归**（静态深度计数，服务器单线程安全）
5. **破法之刃对玩家不生效**（防 PvP 滥用）
6. **`getDisplayName`/`getDescription` 的 `default` 改为按 skillId 拼 key** → 新增技能自动适配，不再需要逐条加 case
