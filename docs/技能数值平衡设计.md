# 技能数值平衡设计（2026-09-14）

> 目标：① 为新增「魔法防护」技能定数值；② 修正现有"标称 1000 级但效果早早封顶"的颗粒度问题；
> ③ 按业界成熟模型重构曲线，并把「上限」从硬封顶改为**可突破**的公式。
> 配套文档：《魔法防护技能调研统计.md》

---

## 一、现状体检（代码实证，问题量化）

### 1.1 现有曲线类型

| 项 | 公式 | 实现位置 |
|---|---|---|
| BASE 基础（上限 1000） | 线性：`点数 × 每点值` | `SkillEffects.applyAll` → `ATTR_TABLE` |
| AMPLIFY 增幅（上限 500） | 乘算：`点数 × 每点值`（`ADD_MULTIPLIED_TOTAL`） | 同上 |
| ULTIMATE 多级 | 指数消耗：`base × (1+10%)^等级` | `Skills.getUltimateLevelCost` |
| AURA | 指数消耗：`base × 1.05^等级` | 同上 |
| GIFT 增幅 | 指数消耗：`1000 × 1.3^等级` | `Skills.getGiftCost` |

### 1.2 🔴 问题一：CRIT / LIFESTEAL 恰好卡在 100%（级别被浪费）

```
critChancePerPoint  = 0.001 (0.1%/点) × 1000 点 = 1.000 = 100%   ← 第 1000 级才刚好到顶
lifestealPerPoint   = 0.001 (0.1%/点) × 1000 点 = 1.000 = 100%
```
代码里 `Math.min(1.0, ...)` 封顶。后果：
- 最后一级的价值是「99.9% → 100%」，与第一级「0% → 0.1%」**数值等效但体感完全不同**
- 玩家无法感知 1000 级的成长（前期暴涨、后期归零）
- 真正的收益应该在"接近上限"时**仍等值**，而不是被截断

### 1.3 🔴 问题二：AMPLIFY 数值彻底失控（比 BASE 强 100 倍）

```
ampHpPerPoint     = 0.1  (10%/点) × 500 点 = 50.0  = +5000%  （51 倍血量）
ampDamagePerPoint = 0.1  (10%/点) × 500 点 = 50.0  = +5000%  （51 倍伤害）
```
对比 BASE：
```
bodyHpPerPoint    = 2.0  (点血) × 1000 点 = +2000 血（原版 20 血 → 101 倍）
bladeDamagePerPoint = 0.4 × 1000 点       = +400 伤害
```
两条曲线**量纲完全不同**（一个是"绝对值"，一个是"×倍率"），导致：
- 增幅列点满 = 直接 51 倍，远超所有终极节点
- 战斗平衡崩塌（一击必杀）
- 级数（500 vs 1000）与强度（×50 vs +400）**不匹配**

### 1.4 🔴 问题三：硬封顶在极低等级就到达

```
UNBREAKABLE 工具不毁：Math.min(1.0, points × 0.2)  → 第 5 级就 100%
ULT_KB_RESIST 击退抗性：每级 +10%                   → 第 10 级就 100%
```
"上限 5 级 / 10 级"本身没问题，但**说明我们已经在用"硬封顶"思路**，
一旦用户想扩到 100 级（用户明确表示"上限我们可以突破上限"），就必须换成公式。

### 1.5 🔴 问题四：全能精通 = 100% 全伤害免疫（见配套调研文档）

```
masterDamageReduction = 1.0  = 完全免疫所有伤害（含真伤/混沌/指令）
虚空神体             = setAmount(0) 完全免疫 + 无冷却不死
```
两个节点都是"绝对无敌"，新增任何防护技能都毫无边际价值。

## 二、业界成熟模型参考（网上成功案例）

数值设计领域有几种被反复验证的模型，**核心都是"显示递减、实际线性"**。

### 2.1 ★★★ 防御类：MOBA 的护甲公式（LoL / Dota / 王者荣耀通用）

$$\text{减伤率} = \frac{D}{D + K} \qquad \Longrightarrow \qquad \text{有效生命倍率} = 1 + \frac{D}{K}$$

- `D` = 防御值，`K` = 平衡常数（LoL 取 100）
- **减伤率永远 < 100%**（渐进逼近，永不无敌）
- 但**有效生命（EHP）随 D 线性增长** → 每点防御的价值恒定！

> 示例（K=100）：D=100 → 减伤 50%，EHP ×2；D=200 → 减伤 66.7%，EHP ×3；
> D=300 → 减伤 75%，EHP ×4。**每 100 点防御都恰好 +1 倍 EHP**。
>
> 这就是"突破上限"的标准答案：不设 100% 上限，让**减伤率**无限逼近但永不达到，
> 而**真实收益（EHP）保持线性**，玩家永远有动力升级。

### 2.2 原神：防御公式

$$\text{承伤倍率} = \frac{5 \times \text{等级} + 500}{\text{DEF} + 5 \times \text{等级} + 500}$$

同 2.1 的思路，常数随等级缩放（防低级号被越级秒杀）。

### 2.3 暗黑破坏神 3 / PoE：「递增 vs 更多」

- **Incremented（加算）**：同类加成直接相加 —— 用于**基础属性**
- **More（乘算）**：独立乘区 —— 用于**稀缺的强力加成**
- 设计铁律：**同类相乘会爆炸，独立乘区要严格控制数量**
- 我们的 AMPLIFY 全部走 `ADD_MULTIPLIED_TOTAL` 且每点 10% → 正是"乘区爆炸"的典型反面教材

### 2.4 WoW / 群星：递减收益（Diminishing Returns）三档曲线

| 曲线 | 公式 | 特点 | 适用 |
|---|---|---|---|
| 线性 | `a × n` | 无上限则线性变强 | 低上限、小数值 |
| 递减 | `a × n/(n+K)` | 渐进逼近上限 | **概率类**（暴击/闪避） |
| 对数 | `a × log(1+n)` | 极强递减 | 大等级范围 |

### 2.5 暴击类：概率饱和模型（解决 1.2 问题）

$$\text{概率} = \text{上限} \times \frac{n}{n + K} \qquad (\text{上限} < 100\%)$$

或双段式：**前期线性、后期递减**
$$\text{概率} = \begin{cases} p_1 \cdot n & n \le n_0 \\ p_1 n_0 + p_2 \ln\frac{n}{n_0} & n > n_0 \end{cases}$$

### 2.6 消耗曲线：指数 vs 多项式

| 公式 | 特点 | 业界用例 |
|---|---|---|
| 指数 `b × r^n` | 后期极陡，硬卡进度 | PoE 宝石、我们的终极 |
| 多项式 `b × n^k` | 平滑，可控 | 大多手游 |
| **混合** `b × n × r^n` | 中后期陡增 | 暗黑 3 巅峰等级 |

> 我们已用 `1.10^等级`（终极）与 `1.05^等级`（光环）——**方向正确**，
> 但**效果曲线没跟上**（消耗指数涨、效果线性封顶 → 后期"花钱买空气"）。

## 三、推荐方案（核心：把「上限」换成公式）

### 3.1 三条总原则

1. **能不用 `Math.min` 就不用** —— 改用渐进公式，让上限"自然到达不了"
2. **收益曲线与消耗曲线同阶** —— 消耗是指数，效果也必须是"递减但持续增长"（对数）
3. **同类加成加算、强力加成独立乘区，且乘区总量受控**（总量 ≤ 若干倍）

### 3.2 防御类统一公式（替换现有 `DAMAGE_REDUCTION` 与 `Math.min`）

```java
/** 
 * 防御值 → 实际减伤率（MOBA 标准式）
 * K 为平衡常数：K 越大，同样防御值的减伤越低（越难堆）
 */
public static double reductionFromDefense(double defense, double K) {
    return defense / (defense + K);      // 永远 < 1，不封顶
}
```

| 场景 | K | 说明 |
|---|---|---|
| 物理减伤（BODY 的 `DAMAGE_REDUCTION`） | 1000 | 与现有 `bodyDrPerPoint = 0.0005` 对齐：1000 点 = 0.5 → 减伤 33% |
| **魔法减伤（新增）** | 1200 | 略高于物理（魔法更稀缺） |
| 元素分化减伤（新增） | 600 | 单一元素容易堆，K 小一点 |

**EHP 视角校验**（K=1000）：防御 500 → 减伤 33%，EHP ×1.5；1000 → 50%，EHP ×2；2000 → 66.7%，EHP ×3。
**每 1000 点防御 = +1 倍 EHP**，线性，永不无敌。

### 3.3 概率类（暴击/吸血/闪避）双段曲线

```java
/**
 * 概率成长（前期线性、后期对数），永不硬顶
 * @param n 等级  @param p1 线性段斜率  @param n0 转折点  @param p2 对数段系数
 */
public static double chanceCurve(double n, double p1, double n0, double p2) {
    return n <= n0 ? p1 * n
                   : p1 * n0 + p2 * Math.log(1.0 + (n - n0) / n0);
}
```
| 技能 | p1 | n0 | p2 | 100 级 | 500 级 | 1000 级 |
|---|---|---|---|---|---|---|
| 暴击几率 | 0.0015 | 400 | 0.12 | 15% | 53% | 73% |
| 生命汲取 | 0.0012 | 400 | 0.10 | 12% | 43% | 59% |

> 对比现状：1000 级死卡 100%（且前期弱）。新曲线**1000 级到 73%**，而且**永远不到 100%**，
> 未来想扩到 2000 级只需 p2 略调，不会失效。

### 3.4 AMPLIFY 修正（消除 51 倍爆炸）

现状 `每点 10% × 500 点 = +5000%`。改为**递减乘区**：

$$\text{总倍率} = 1 + \text{上限} \times \frac{n}{n + K_{\text{amp}}}$$

| 技能 | 上限 | K | 100 级 | 500 级 | 说明 |
|---|---|---|---|---|---|
| 血魄真解（生命 ×） | +200% | 300 | +50% | +125% | 上限 3 倍 |
| 剑心真解（伤害 ×） | +200% | 300 | +50% | +125% | 与生命对称 |
| 其余增幅 | +150% | 250 | — | — | 统一口径 |

> 500 级从"51 倍"降到"3 倍"，与 BASE 的绝对值曲线量级相当。
> 若用户希望"能突破"，把上限设为可配置即可（公式天然接受任意上限）。

### 3.5 全伤害免疫 → 分级化（解决 1.5）

把「全能精通 100% 免疫」拆成两个维度，各自用 3.2 的公式：

| 层 | 原设计 | 新设计 |
|---|---|---|
| 全能精通 | 全伤害 ×(1-1.0) = 免疫 | **物理减伤 80% + 魔法减伤 60%**（可配置），仍极强但不无敌 |
| 虚空神体 | 全伤害 → 0 + 无冷却不死 | **物理/魔法减伤各 95%** + 不死保留（冷却大幅缩短） |
| 新增魔防前置 | — | 补足那 20%/40% 的缺口 → 让"毕业"的路径体现魔防价值 |

> 「毕业 = 接近无敌」的体验保留（95% 减伤 ≈ EHP ×20），但**不再是与数字无关的"绝对免疫"**，
> 且玩家的**等级提升永远有意义**（95% → 95.5% 仍是真实收益）。

## 四、新增「魔法防护」技能数值表（草案）

### 4.1 基础层（MAGIC 列，多级，吃增幅）

| # | 技能 | 等级上限 | 效果公式 | 100 级 | 1000 级 | 消耗曲线 |
|---|---|---|---|---|---|---|
| ① | **奥术壁垒** | 1000 | 魔抗 = `n × 0.6` → 减伤 = `D/(D+1200)` | 5.7% | 33% | 线性 2 |
| ② | **法抗淬炼** | 1000 | 同上但作用于"元素伤害"细分 | — | — | 线性 2 |
| ③ | **元素亲和** | 500 | 每系独立：`n × 0.4`，`K=600` | 6.3% | — | 线性 3 |
| ④ | **法术抑制** | 500 | 只减**间接伤害**：`n × 0.5`，`K=800` | 5.9% | — | 线性 3 |

> 全走 3.2 公式 → **无上限、每级等值、永不无敌**。
> ①②为"总量"，③为"分系"，④为"限定类型"（数值可更高，因为覆盖面窄）。

### 4.2 增幅层（对应 4.1，500 级）

| 技能 | 效果 | 公式 |
|---|---|---|
| 奥术真解 | 提升 ① 的防御值 | `+ n × 0.4`（直接加到防御值上，再走同一公式） |
| 元素真解 | 提升 ③ | 同上 |

> 关键：**增幅作用于"防御值"而不是"减伤率"** —— 这样增幅的收益也自动线性化（EHP 线性），
> 避免出现"增幅把减伤从 95% 推到 100%"的爆炸。

## 五、改造影响与迁移方案

### 5.1 影响范围

| 文件 | 改动 |
|---|---|
| `SkillEffects.java` | ③处 `Math.min` 换成曲线函数；AMPLIFY 乘算改递减式 |
| `Config.java` | 新增 `K` 常数与上限配置项；调整 `amp*PerPoint` 默认值 |
| `Skills.java` | 新增技能常量/分组/前置/图标/消耗 |
| `UltimateEvents.java` | 全能精通/虚空神体减伤分级化；新增 4.3 的 6 个机制 |
| `lang/*.json` ×4 | 新增技能的 name/desc（双语） |

### 5.2 ⚠️ 老存档兼容

- **数值下调是不可逆的体验变化**（AMPLIFY 从 51 倍 → 3 倍）→ 必须在更新日志里**明确告知**
- 建议提供 Config 开关 `legacyScaling = false`，允许整合包作者回退旧曲线
- 已学习的技能等级**保留**（只改效果计算，不动存档数据）

### 5.3 实施顺序建议

1. **先做公式函数**（`reductionFromDefense` / `chanceCurve` / 递减乘区）—— 独立、可单测
2. **再改现有 4 处封顶**（CRIT / LIFESTEAL / UNBREAKABLE / KB_RESIST）—— 风险最低、见效最快
3. **然后加分级化**（全能精通 / 虚空神体）—— 影响平衡，需实测
4. **最后加新技能**（4.1~4.4）
